This page has two parts:

1. **Run provenance** (hand-written from each year's run records): which engine,
   configuration, seed, inputs and environment produced each year, and how to
   check a file you hold against them.
2. **Dataset provenance** (generated by `scripts/gen_provenance.py`): one row per
   declared dataset, with its upstream sources, publisher, licence, transform
   and assumptions.

## Checking a file you hold

1. Every Parquet part has a sidecar `<dataset>_partNNN.manifest.json` with
   `file_sha256` (the file's bytes), `content_hash_sha256` (its content),
   `rows`, `schema_version`, `schema_conformance`, `access_class` and
   `release_package`. `sha256sum` on the file should equal `file_sha256`.
2. A year's datasets and row counts should match `_segment/DONE.json`
   `row_counts`. The absent ones and their reasons are in
   `_segment/export_report.json`.
3. Each year on B2 was checked against the instance's copy with `rclone check`
   (0 differences) at upload, and the whole of `v1/` again at completion.

# Part 2 — dataset provenance

## Baile Nua / HRSD_Occupants — provenance

**UNVALIDATED SIMULATION EVIDENCE: E1 engineering candidate**

One row per declared dataset: what it is, every upstream source that could be attributed to it with its publisher and licence, the module and function that produces it, and the `[A]` assumption numbers it depends on.

Generated by `scripts/gen_provenance.py`. Checked by `scripts/validate_provenance.py` against D23 (run manifests, for the source digests) and D24 (calibration targets, for the assumption and source register). **Do not edit by hand** — regenerate.

### How to read this, and what it does not claim

The repository declares **no dataset-to-source mapping**: `schema/datasets.yaml` has no `sources` key and `sources_registry.py` has no `datasets` key. Every citation below is therefore *inferred*, by three channels, and each one carries the module it was attributed through so a reader can reject it:

1. the **producer** — `export.dispatch.EXPORTERS`, or the `StreamWriter` method that buffers the dataset;
2. the dataset's **subsystem** package, from the schema's `subsystem` field and the design r4 §4 subsystem table;
3. any other module that **names the dataset id**, excluding the scoring packages (a source a scoring module reads is one the dataset is compared against, not built from) and the registries that name more than 10 datasets.

The inference can be wrong in both directions. It misses a source that reaches a dataset only through a module that never names it, and it over-claims when a module mentions a dataset for an unrelated reason. The fix is to declare the mapping in `datasets.yaml`; this page is not that fix.

A citation resolves only when a file under `sources/` exists **and** a `*.manifest.json` sits beside it carrying its SHA-256, publisher, licence and retrieval date. One that does not is marked <span style="color:red">UNSOURCED</span>.

**Today: 32 datasets. 28 resolve fully (at least one citation, every citation resolved). 0 carry at least one <span style="color:red">UNSOURCED</span> citation. 4 have no citation at all.**

10 of the 81 manifests under `sources/` are **present on disk but not committed**, so a reader of the committed tree would not find them. They resolve here because the bytes and the record are both on this disk, and the citation says so: `sources/cso_census2016/SAPS2016_SA2017.csv`, `sources/cso_census2016/SAPS_2016_Glossary.xlsx`, `sources/derived/smart_meter_rollout.csv`, `sources/esri/ESRI_WP824_price_elasticity_residential_gas.pdf`, `sources/eu_oil_bulletin/Weekly_Oil_Bulletin_Prices_History.xlsx`, `sources/eu_oil_bulletin/cso_cpm18_home_heating_oil_monthly.csv`, `sources/eu_oil_bulletin/ie_heating_gas_oil_weekly.csv`, `sources/gaa/all_ireland_finals_2015_2026.csv`, `sources/osi_boundaries/Small_Areas_Generalised_20m_2015.geojson`, `sources/wrc/wrc_public_holidays.html`.

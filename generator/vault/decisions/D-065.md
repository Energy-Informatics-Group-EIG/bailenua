## Decision

Correlated events come from a shared driver that each event names, and driver_audit refuses an event claiming a driver that does not generate it

## Reason

Design 5.10 says compound correlation comes from shared drivers. Outages drawn independently of the weather would put the lights out on a calm day, and a model that had learned the real storm-outage correlation would then be penalised for being right. K09 adds the reason it has to be recorded: a pairwise matrix over ten event kinds is not validatable, so validation is by class and by driver, which is only possible if the driver is in the data. 86% of multi-kind days are driver-explained and 5 are genuine chance overlaps. State kinds are excluded from the count - a six-week term overlapping a fixture is a Saturday, and counting it buried the five that meant something

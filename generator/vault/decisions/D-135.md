# D-135 — resume is per SEGMENT, and an incomplete segment is renamed aside.

| | |
|---|---|
| Kind | implementation decision |
| Recorded in | `docs/DECISIONS.md replay section` |

## Decision

A killed segment is re-run from the previous segment's final checkpoint rather than from its own latest checkpoint. Two reasons, and the first is correctness: StreamWriter numbers its Parquet parts from zero, so resuming mid-segment into an existing package directory would leave the dead attempt's higher-numbered parts in place and the package would silently hold two attempts.

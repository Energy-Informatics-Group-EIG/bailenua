## Decision

The dataset manifest's content hash (hash_frame) is row-order sensitive and column-order independent, reversing the Day-1 choice; the old behaviour is kept as hash_frame_row_order_independent

## Reason

I-030. The row-wise canonical-JSON hash cost 32.8 s of a 47 s writer — several times the simulation it was recording — and, more importantly, pointed the wrong way: a row-order independent hash calls two different byte streams "the same content", and design 9.2's criterion is *byte-identical* output. It could only ever hide a determinism failure. Every dataset is written in a deterministic order anyway, so there is no legitimate reordering for it to absorb
